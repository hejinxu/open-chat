## 1. 背景与目标

### 1.1 背景

随着大语言模型生态的成熟，企业和开发者面临一个新的痛点：**智能体平台选型锁定**。

市面上主流的智能体后端平台（Dify、FastGPT、n8n、Coze 等）各有优势，但它们的对话前端通常是各自封闭的。这意味着：
- **切换成本高**：一旦选定某个平台并集成其前端，迁移到另一个平台需要重写大量前端代码
- **无法统一管理**：一个组织可能同时使用 Dify 做客服、FastGPT 做知识问答、直连大模型做内部工具，但缺乏统一的对话入口和管理后台
- **嵌入困难**：第三方网站想集成 AI 对话能力，通常需要针对每个后端平台单独适配，缺乏开箱即用的嵌入方案
- **语音交互割裂**：语音识别（ASR）作为对话系统的核心入口之一，往往与对话系统独立部署，缺乏统一的认证和管理

**核心问题**：市场缺少一个**后端无关**的对话客户端层——它不生产智能体，而是连接所有智能体。

这个项目的目标就是构建这样一个"对话中间件"：一个统一的对话界面 + 管理后台，通过适配器模式对接多种智能体后端，让使用者**接入新智能体只需在后台填一个表单，而非写一行代码**。

## 2. 用户角色

### 2.1 系统角色

| 角色 | 描述 | 权限 |
|------|------|------|
| **系统管理员** | 平台运维人员 | 全部管理功能（用户、智能体、系统配置） |
| **普通用户** | 使用对话功能的用户 | 选择智能体、发起对话、查看对话历史 |
| **外部集成方** | 通过 API Key 嵌入对话组件的第三方 | 指定智能体的对话能力（受 API Key 权限约束） |

### 2.2 组织角色（规划中）

| 角色 | 描述 | 权限 |
|------|------|------|
| **组织所有者 (owner)** | 组织创建者 | 管理组织成员、配置、对话 |
| **组织管理员 (admin)** | 组织管理者 | 管理成员、对话，查看统计 |
| **组织成员 (member)** | 普通成员 | 使用对话功能 |

## 3. 功能需求概要

### 3.1 对话客户端

- 统一的对话界面，支持文本输入、文件上传、语音输入
- 智能体选择器：在输入框内切换不同后端智能体
- 对话管理：新建、切换、删除对话；对话标题自动生成
- 消息渲染：Markdown、代码高亮、流式输出
- 消息操作：重新生成、复制、反馈（点赞/点踩）、删除
- SSE 流式响应，实时显示 AI 回复

### 3.2 管理后台

- **用户管理**：创建、编辑、启用/禁用用户；角色分配（admin/user）
- **智能体管理**：创建、编辑、删除智能体；配置后端类型、API URL、API Key、模型；启用/禁用、设为默认
- **应用集成管理**：创建应用集成（OAuth），生成 API Key，控制可访问的智能体范围

### 3.3 嵌入式对话组件

- 第三方网站通过 `<script>` 标签引入，一行代码集成
- 浮动按钮 + 弹窗式对话窗口
- 支持拖拽移动、调整窗口大小、位置/尺寸持久化
- 支持自定义主题、图标、窗口标题
- API Key 认证，受中间件保护

### 3.4 语音识别服务

- 独立 WebSocket 服务，支持 Whisper 和 FunASR 引擎
- 支持自动停顿检测（静音超时自动停止录音）
- 浏览器原生语音识别作为备选引擎
- 远程认证：token 验证委托给主应用

### 3.5 认证系统

- **Level 1（简单集成）**：API Key（`sk-xxx`）认证，适用于嵌入式组件
- **Level 2（服务端集成）**：OAuth（app_id + app_secret）认证，支持用户身份映射
- Session Cookie（关闭浏览器自动过期）
- 中间件全局验证，未认证请求重定向到登录页

### 3.6 智能编排（规划中）

- **自主路由**：用户提问后，编排层自动分析问题意图，选择最合适的智能体执行，无需用户手动选择
- **全局 Skills**：统一的技能注册中心（如搜索、代码执行、文件处理、外部 API），智能体通过配置声明可调用的 skills，运行时按需调用
- **任务规划**：面对复杂任务，自动拆解为多步骤执行计划，计划过程对用户可见（展示"我将分几步完成"）
- **多智能体协作**：一个任务可分配给多个智能体分别执行，最终汇总结果
- **执行监控**：用户可实时查看每个步骤的执行状态、调用的智能体、使用的 skills

## 5. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 现有路由兼容性 | 切换 agent 后旧会话可能异常 | 无 `X-Agent-Id` 时 fallback 到 `.env` 配置 |
| api_key 安全 | 数据库泄露导致密钥暴露 | 依赖 DB 权限控制，后续版本加密 |
| DirectLLM 对话历史 | 无原生对话管理 | 本地 DB 存储对话/消息 |
| 性能 | 每次请求查 DB 加载配置 | 内存缓存（LRU），TTL 5 分钟 |
| JWT 密钥泄露 | 账号被盗用 | 环境变量存储，定期轮换 |
