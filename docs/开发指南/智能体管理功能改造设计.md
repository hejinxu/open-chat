# 智能体管理功能改造设计

> 本文档记录智能体管理功能的改造设计方案，包括智能体类型、数据源管理、业务知识配置等功能。

---

## 一、需求背景

当前智能体管理页面只有基础配置（名称、后端类型、执行模式、模型等），需要扩展支持：
1. **智能体类型**：区分通用智能体和专有智能体（如问数智能体）
2. **数据源配置**：问数智能体需要连接数据库，选择表和字段
3. **业务知识**：定义业务术语、查询规则，帮助 AI 理解业务语义
4. **查询示例**：提供示例问题和 SQL，帮助 AI 学习查询模式
5. **系统提示词**：自定义智能体的行为指导

---

## 二、概念模型

### 2.1 四个正交维度

| 维度 | 含义 | 选项 |
|------|------|------|
| **智能体类型** | 领域定位（做什么） | 通用智能体、问数智能体 |
| **后端类型** | 技术实现（怎么做） | Dify、直连大模型、FastGPT、n8n |
| **执行模式** | 推理策略（怎么想） | 纯对话、ReAct、Plan-And-Execute |
| **模型** | 具体 LLM | GPT-4o、DeepSeek 等 |

### 2.2 智能体类型定义

| 类型 | 标识 | 说明 | 额外配置 |
|------|------|------|----------|
| 通用智能体 | `general` | 默认类型，无特殊领域定位 | 无 |
| 问数智能体 | `data_query` | 专用于数据查询 | 数据源、业务知识、查询示例 |

### 2.3 智能体类型约束

| 智能体类型 | 后端类型约束 | 执行模式约束 |
|-----------|-------------|-------------|
| 通用智能体 | 可选任意（Dify、直连大模型、FastGPT、n8n） | 根据后端类型显示（仅直连大模型时显示） |
| 问数智能体 | 仅限 `直连大模型`，自动选中且不可修改 | 仅限 `ReAct`，自动选中且不可修改 |

**设计理由**：
- 问数智能体需要调用工具（执行 SQL 查询），因此必须使用支持工具调用的后端和执行模式
- ReAct 模式支持"思考→调用工具→继续推理"的循环，适合数据查询场景
- 选择问数智能体时自动设置后端类型和执行模式，减少用户配置负担

### 2.3 Tab 显示矩阵

| Tab | 通用智能体 | 问数智能体 |
|-----|-----------|-----------|
| 基本配置 | ✅ | ✅ |
| 模型参数 | ✅（仅直连大模型） | ✅（仅直连大模型） |
| 数据源 | ❌ | ✅（两页：列表+表字段选择） |
| 业务知识 | ❌ | ✅ |
| 系统提示词 | ✅（仅直连大模型） | ✅（仅直连大模型） |
| 其他配置 | ✅ | ✅ |

### 4.2 agent_config 完整结构

```typescript
interface AgentConfig {
  // 数据源列表（问数智能体，可多个）
  datasources?: Array<{
    id: string                                    // 唯一标识
    name: string                                  // 显示名称（如"订单库"）
    type: 'mysql' | 'postgresql'                  // 数据库类型
    host: string                                  // 主机地址
    port: number                                  // 端口
    database: string                              // 数据库名
    username: string                              // 用户名
    password_encrypted: string                    // 加密存储的密码
    is_active: boolean                            // 是否为当前活跃数据源
    selected_tables?: string[]                    // 选中的表
    selected_columns?: Record<string, string[]>   // 选中的字段
    schema_overrides?: Record<string, {           // 自定义注释覆盖
      comment: string | null
      columns: Record<string, { comment: string | null }>
    }>
  }>

  // 业务知识（问数智能体，与数据源无关）
  business_knowledge?: Array<{
    id: string
    term: string              // 术语名称
    definition: string        // 定义/说明
    field_mapping?: string    // 可选：对应字段
    sql_expression?: string   // 可选：SQL 表达式
  }>

  // 查询示例（问数智能体，与数据源无关）
  query_examples?: Array<{
    id: string
    question: string          // 用户问题
    sql: string               // 对应 SQL
    explanation?: string      // 可选：说明
  }>

  // 系统提示词（仅直连大模型）
  system_prompt?: string
}
```

## 五、运行时数据流

### 5.1 问数请求链路（提示词拼接流程）

> 最新实现由 `lib/services/data-query-pipeline.ts` 编排，`app/api/chat-messages/route.ts` 只负责 HTTP / 认证 / 区划注入 / 流式响应。

```
用户提问: "上个月营收多少？"
    ↓
获取智能体配置，判断 agent_type == data_query
    ↓
① 查询规范化（lib/services/query-normalize.ts）
   多轮指代消解 + 相对时间换算（"上个月" → 明确日期范围，注入当前时间）
   得到 canonical_query；仅当含相对时间词、或有历史且含指代/追问词时触发（自包含问题不改写，避免指标语义漂移），失败回退原始问题
    ↓
② 表选择（lib/services/schema-select.ts）
   实时拉取表清单（表名+表注释+列数，TTL 缓存）→ LLM 挑选相关表
   → 与配置的 selected_tables 求交集（防止臆造表名）
    ↓
③ 实时 Schema 拉取 + 子集 DDL
   拉取选中表的列名/类型/注释/主键/外键（information_schema，TTL 缓存）
   注释优先级：用户自定义注释(schema_overrides) > 数据库实时注释 > 配置快照
    ↓
④ 拼接系统提示词（lib/prompts/index.ts buildSystemPrompt）
   内置提示词（含完整指令边界）+ 补充提示词 + 动态提示词 + 联网状态
   动态提示词 = 数据源类型 + 表结构（选中表子集 DDL）+ 业务知识 + 查询示例
   表结构段为运行时 ddlSection（选中表），未选中表不进上下文
    ↓
⑤ ReAct Agent 执行（lib/executors/agent-executor.ts）
   agent 收到 canonical_query（替换最新用户消息，历史保留）+ 系统提示词
    ↓
⑥ SQL 执行（lib/tools/builtin/execute-sql.ts）
   validateReadOnlySql 强制只读校验 → 代码级结构校验（拦截不存在的表/列，零 LLM）→ 连接级只读事务 → 执行
    ↓
格式化返回给用户（业务化表述，严禁展示字段名/表名/枚举编码等底层细节）
```

每个阶段均支持独立开关，任一步失败自动降级到基础问数能力，不阻断请求。

### 5.2 Schema 与 DDL 生成逻辑

**数据来源**：运行时从数据库 `information_schema` **实时拉取**（`fetchSelectedTableSchemas`，带 TTL 内存缓存 60s），不依赖配置时保存的快照（快照可能过期：列注释缺失、列结构变更）。

**注释优先级**（`buildDDLFromSchema`）：

```
用户自定义注释（schema_overrides.columns[col].comment）   ← 永远优先
   > 数据库实时注释（COLUMN_COMMENT / obj_description）
   > 配置快照 original_comment
```

列类型 / 主键 / 外键以数据库实时为准，快照仅作兜底。

**运行时子集 DDL**：表选择后只生成选中表的 DDL，未选中表不进上下文，避免大库全量 DDL 撑爆上下文窗口。

**配置时快照 DDL**（`generateDDL`，`lib/prompts/dynamic-prompt.ts`）仍保留，作为实时拉库失败时的兜底路径。

## 七、联网控制功能

### 7.1 功能说明

当智能体使用 ReAct 或 Plan-And-Execute 执行模式时，可能需要调用联网工具（搜索、网页抓取等）。为防止模型在无法联网的环境中浪费时间尝试联网，增加"联网控制"开关。

### 7.2 字段定义

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enable_network` | `boolean` | `false` | 是否支持联网搜索 |

**显示条件**：仅当执行模式为 `react` 或 `plan_and_execute` 时显示

### 7.3 工具限制策略

| 工具 | 场景 | 是否受限 | 原因 |
|------|------|---------|------|
| `web_search` | 搜索互联网 | ✅ 受限 | 必须联网 |
| `fetch_url` + URL | 抓取指定网页 | ❌ 不受限 | 可能是内网页面 |
| `fetch_url` + 搜索关键词 | 搜索互联网 | ✅ 受限 | 必须联网 |
| `http_request` | HTTP 请求 | ❌ 不受限 | 可能调用业务接口 |

### 7.4 UI 设计

位于"基本配置" Tab，仅当执行模式为 ReAct 或 Plan-And-Execute 时显示：

```
┌─────────────────────────────────────────────────────────────┐
│ ☐ 允许联网搜索                                              │
│                                                             │
│ 开启后，智能体可以使用搜索和网页抓取工具获取互联网信息。      │
│ 关闭后，智能体仅使用本地知识和数据库进行回答。               │
│                                                             │
│ 注意：HTTP 请求工具不受此设置影响，仍可用于调用业务接口。     │
└─────────────────────────────────────────────────────────────┘
```

### 7.5 系统提示词增强

当 `enable_network === false` 时，在系统提示词末尾添加：
```
注意：当前环境不支持联网搜索，你无法访问互联网获取实时信息。
请基于已有知识和数据库数据回答问题，不要尝试使用搜索或网页抓取工具。
HTTP 请求工具可用于调用业务系统接口。
```

当 `enable_network === true` 时，在系统提示词末尾添加：
```
你可以使用联网搜索和网页抓取工具获取互联网上的最新信息。
```

### 7.6 动态提示词

**概念**：动态提示词是由数据源配置、业务知识、查询示例自动生成的提示词片段，存储在 `agent_config.dynamic_prompt` 中。

**生成时机**：
- 配置变更时自动更新（勾选表/字段、编辑业务知识、编辑查询示例）
- 用户手动点击"重新生成"按钮

**组成**：
```
动态提示词 = 数据源类型 + 表结构（DDL）+ 业务知识 + 查询示例
```

**运行时使用**：
```
最终提示词 = 内置提示词（含指令边界） + 补充提示词 + 动态提示词 + 联网状态
```

**运行时表结构段替换（ddlSection）**：表选择成功后，请求链路会用**选中表的子集 DDL** 替换动态提示词中的"# 数据表结构"段（`buildSystemPrompt` 的 `options.ddlSection`），存储的全量 DDL 仅作为降级兜底。

**使用边界说明**（防止模型误用）：
- 业务知识/查询示例段前注入"仅作参考数据"说明：示例值不得当作真实过滤值、不得创造表结构中不存在的字段、冲突定义保留差异。
- 表结构段前注入"仅供编写 SQL 参考，严禁向用户展示字段名/表名/字段定义"。

**优势**：
- 大库场景只注入相关表 DDL，显著降低 token 消耗，避免上下文窗口超限
- 用户可预览最终提示词，确认无误后再使用
- 用户可手动微调生成的提示词

### 7.7 问数链路开关配置

## 八、execute_sql 工具

### 8.1 功能说明

为问数智能体提供 SQL 查询执行能力，连接到配置的数据源执行查询并返回结果。

### 8.2 安全防护（三层防护）

| 层级 | 防护措施 | 说明 |
|------|----------|------|
| **第 1 层：应用层过滤** | `validateReadOnlySql()` | 检查 SQL 关键词，仅允许 SELECT/WITH |
| **第 2 层：连接级只读** | 数据库事务设置 | MySQL: `SET SESSION TRANSACTION READ ONLY`<br>PostgreSQL: `SET default_transaction_read_only = true` |
| **第 3 层：结果限制** | 自动添加 LIMIT | 默认最多返回 100 行 |

### 8.3 应用层过滤规则

```typescript
// 1. 禁止多语句执行
const withoutTrailingSemicolon = normalized.replace(/;\s*$/, '')
if (withoutTrailingSemicolon.includes(';')) {
  return { valid: false, error: '不允许执行多条 SQL 语句' }
}

// 2. 移除字符串内容后再检查关键词（避免误判）
const withoutStrings = normalized
  .replace(/'[^']*'/g, '')
  .replace(/"[^"]*"/g, '')

// 3. 检查危险关键词
const dangerousKeywords = [
  'INSERT', 'UPDATE', 'DELETE', 'DROP', 'ALTER', 'TRUNCATE',
  'CREATE', 'GRANT', 'REVOKE', 'EXEC', 'EXECUTE',
  'INTO', 'REPLACE', 'MERGE', 'UPSERT',
]
// 注意：SET 已移除，因为可能作为列别名或函数名

// 4. 必须以 SELECT 或 WITH 开头
if (!normalized.startsWith('SELECT') && !normalized.startsWith('WITH')) {
  return { valid: false, error: '仅允许 SELECT 查询语句' }
}
```

### 8.4 工具参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sql` | string | ✅ | SQL 查询语句（仅支持 SELECT） |
| `limit` | number | ❌ | 返回结果最大行数（默认 100） |

### 8.5 返回格式

```json
{
  "success": true,
  "data": {
    "columns": ["id", "name", "revenue"],
    "rows": [
      { "id": 1, "name": "客户A", "revenue": 10000 },
      { "id": 2, "name": "客户B", "revenue": 8000 }
    ],
    "row_count": 2
  }
}
```

### 8.6 工作流程

```
用户提问: "上个月营收多少？"
    ↓
查询规范化 → canonical_query（指代消解 + 相对时间换算）
    ↓
AI 读取动态提示词（选中表 DDL、业务知识、查询示例）
    ↓
AI 生成 SQL: SELECT SUM(revenue) FROM orders WHERE ...
    ↓
AI 调用 execute_sql 工具
    ↓
validateReadOnlySql() 验证安全性（只读/单语句/危险关键词）
    ↓
结构校验（可选，默认开启，enable_semantic_check；代码级，零 LLM）
   解析 SQL 引用表和列 → 与实时 schema 比对 → 拦截不存在的表或列（如 YEAR）
   失败 → 返回友好错误，AI 据此修正 SQL 后重试
    ↓
同请求重复查询拦截：归一化后的相同 SQL 直接返回缓存结果（不重复查库），并在成功结果附带引导，提示 AI 已能回答时直接作答
    ↓
设置连接级只读事务
    ↓
执行查询（超时 180 秒）并返回结果
    ↓
AI 解读结果并回答用户（业务化表述，严禁展示字段名/枚举编码等底层细节）
```

### 8.7 查询超时

| 数据库 | 超时设置 | 说明 |
|--------|----------|------|
| MySQL | 查询级 180 秒 | `queryTimeout: 180000`（查询级，非连接级） |
| PostgreSQL | 查询级 180 秒 | `query_timeout: 180000`（查询级） |

## 十、ReAct Agent 强制总结改进

### 10.1 问题背景

当工具调用次数达到上限（默认 10 次）时，Agent 会进入"强制总结"节点。
原有实现只是泛泛地总结工具调用结果，可能无法回答用户的原始问题，导致返回无关内容。

### 10.2 改进方案

强制总结时：
1. 提取用户的原始问题
2. 将原始问题 + 工具调用结果一起发送给 LLM
3. 要求 LLM 直接回答问题，如果无法回答则明确告知用户

### 10.3 提示词模板

```
用户问题：{原始问题}

以下是工具调用获取的数据：
{工具调用结果}

请根据以上数据回答用户的问题：
- 如果数据足以回答，请直接给出答案
- 如果数据不足以回答或查询失败，请明确告知用户"查询未能完成，已达到工具调用次数限制，请重试或简化问题"
- 不要编造数据或猜测答案
- 不要总结工具调用过程，只关注回答用户的问题
```

### 10.4 工具调用限制

| 限制类型 | 阈值 | 说明 |
|----------|------|------|
| 搜索工具轮数 | 5 次 | `fetch_url`、`web_search` 等联网工具 |
| 总工具轮数 | 12 次 | 所有工具调用总计，达上限强制总结 |
| 图递归上限 | 64 | `recursionLimit`，必须大于总工具轮数的 2 倍，确保强制总结先于图递归异常触发 |
