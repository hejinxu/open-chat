# 第三方应用集成指南

> 面向希望在自己的 Web 应用中嵌入 open-chat 对话功能的开发者。
> 前提：open-chat 服务已部署并正常运行。

## 快速开始

### 1. 获取 API Key

1. 打开 open-chat 管理面板（`http://your-server.com/admin`）
2. 进入「系统集成管理」页面
3. 点击「添加应用集成」，填写名称和描述
4. 在集成列表中点击「API Key」按钮
5. 输入 Key 名称，点击「生成密钥」
6. **立即复制**显示的完整 `sk-xxx` 密钥（关闭后无法再查看）

> `allowed_agent_ids` 在管理面板中配置，设为 `*` 表示允许使用全部智能体。

### 2. 在网页中引入

```html
<!-- 1. 配置 (放在 <script> 引入之前) -->
<script>
window.openChatConfig = {
  baseUrl: 'http://your-server.com',
  apiKey: 'sk-embed-default-a1b2c3d4',
}
</script>

<!-- 2. 引入脚本 -->
<script src="http://your-server.com/embed.min.js" defer></script>
```

> **注意**：如果 open-chat 部署在子路径下（`NEXT_PUBLIC_BASE_PATH=/chat`），`baseUrl` 和脚本 `src` 都需要加上前缀：
> ```html
> baseUrl: 'http://your-server.com/chat'
> <script src="http://your-server.com/chat/embed.min.js" defer></script>
> ```

### 3. 完成

刷新页面，右下角会出现浮动对话按钮。点击即可开始对话。

## 配置参数说明

### 必填参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `baseUrl` | `string` | open-chat 服务器地址，不含尾部 `/`。示例：`'http://localhost:3000'` |
| `apiKey` | `string` | API Key，由 open-chat 管理员在管理面板生成（格式：`sk-xxx`）。校验不通过则所有 API 返回 401 |

### 可选参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `agentId` | `string` | 无 | 预设智能体 ID。不填则使用默认智能体。若指定的 ID 不存在或已被禁用，自动回退到默认智能体 |
| `icon` | `string` | `'robot'` | 内置图标名称（共 14 个） |

### 内置图标

| 名称 | 图标 | 场景 |
|------|------|------|
| `robot` | 机器人 | 通用 AI 助手（默认） |
| `bot` | 双屏机器人 | 备选风格 |
| `chat` | 聊天气泡 | 客服 / 对话 |
| `sparkle` | 星光 | 智能助手 |
| `headset` | 头戴耳机 | 人工客服 |
| `message` | 信封 | 消息中心 |
| `brain` | 大脑 | 智能分析 / 推理 |
| `wand` | 魔法棒 | AI 创作 / 生成 |
| `rocket` | 火箭 | AI 效率提升 |
| `puzzle` | 拼图 | 解题 / 逻辑推理 |
| `eye` | 眼睛 | 视觉分析 / 识别 |
| `code` | 代码 | 编程助手 |
| `gear` | 齿轮 | 系统管理 |

> 来源：`webapp/public/images/embed-icons/` 目录。设置 `iconUrl` 可覆盖内置图标。
| `iconUrl` | `string` | 无 | 自定义图标 URL。设置后覆盖 `icon` |
| `windowTitle` | `string` | `'AI 助手'` | 窗口标题栏文字 |
| `theme` | `string` | `'light'` | 主题：`light` / `dark` / `tech-blue` |
| `locale` | `string` | `'zh-Hans'` | 语言 |
| `inputs` | `object` | `{}` | 预设参数，填入智能体的 prompt_variables |

| `onCommand` | `function` | 无 | 指令回调。AI 回复中若包含 `<!-- COMMAND:{...} -->` 指令，解析后调用此函数 |
| `getAgentParams` | `function` | 无 | 参数注入回调。切换智能体、切换会话、每次发送前调用，宿主返回参数值 |

### 浮动按钮位置

支持两种格式：

**命名预设** — 四角位置，距边缘 24px：

```javascript
bubblePosition: 'bottom-right'  // 默认
bubblePosition: 'bottom-left'
bubblePosition: 'top-right'
bubblePosition: 'top-left'
```

**精确像素** — 指定任意方向偏移量（px）：

```javascript
bubblePosition: { right: 24, bottom: 24 }   // 等同 'bottom-right'
bubblePosition: { left: 24, bottom: 48 }    // 左下角，距底 48px
bubblePosition: { right: 48, top: 24 }      // 右上角
```

> 用户拖拽按钮后，位置保存到 localStorage，后续访问不再使用配置值。清除 `open_chat_embed_state` 可恢复到配置位置。

### 窗口尺寸

```javascript
windowSize: {
  width: 420,        // 初始宽度 (px)，默认 400
  height: 640,       // 初始高度 (px)，默认 600
  minWidth: 320,     // 最小宽度，用户拖拽 resize 下限
  minHeight: 400,    // 最小高度
  maxWidth: 800,     // 最大宽度
  maxHeight: 900,    // 最大高度
}
```

窗口尺寸和位置会持久化到 localStorage (`open_chat_embed_state`)，下次打开恢复。

### 标题栏样式

```javascript
headerStyle: {
  backgroundColor: '#1C64F2',           // 标题栏底色
  borderColor: 'rgba(255,255,255,0.2)',  // 标题栏底边
  textColor: '#ffffff',                 // 标题文字色
  iconColor: '#ffffff',                 // ☰ 和 × 图标色
  buttonHoverBg: 'rgba(255,255,255,0.15)',  // 按钮悬停底色
}
```

不填则按 `theme` 取对应默认值。

### 浮动按钮样式

```javascript

  backgroundColor: '#1C64F2',  // 按钮底色。设置了 iconUrl 或使用内置 icon 时仅作 fallback

```

## 移动端行为

屏幕宽度 ≤ 768px 时自动切换为全屏模式：
- 弹窗覆盖整个屏幕
- 隐藏 resize handle
- 标题栏不可拖拽
- 关闭按钮仍然可用

用户可以在移动端正常对话，关闭后恢复浮动按钮。从移动端切换到桌面端时，窗口自动恢复为预设尺寸。

## 位置持久化

| 存储 Key | 内容 |
|----------|------|
| `open_chat_embed_state` | 统一状态 `{ btn: {x, y}, win: {w, h, x, y} }` |

- `btn`：浮动按钮位置（拖拽后保存）
- `win`：窗口大小 + 位置（resize 或标题栏拖拽后保存）
- 无保存数据时：窗口默认右下角，大小取 `windowSize` 配置

均存储在用户浏览器的 localStorage 中，刷新页面后保持不变。

## AI 指令（Command）

AI 回复中可以包含操作指令，嵌入弹窗会自动解析并通过 `postMessage` 发送给宿主页面。

### 指令格式

AI 后端在回复中嵌入 HTML 注释格式的指令：

```
我来为您打开百度。

<!-- COMMAND:{"action":"openPanel","params":{"url":"https://www.baidu.com"}} -->
```

多条指令直接写多个注释块：

```
我来为您打开百度和谷歌。

<!-- COMMAND:{"action":"openPanel","params":{"url":"https://www.baidu.com"}} -->
<!-- COMMAND:{"action":"openPanel","params":{"url":"https://www.google.com"}} -->
```

- `COMMAND:` 前缀区分普通注释和操作指令
- 指令在对话界面中不可见（浏览器不渲染 HTML 注释）
- 一条回复可包含多个指令

### 宿主接收方式

嵌入弹窗检测到指令后，通过 `postMessage` 发送给宿主页面。宿主有两种接收方式：

**方式一：`onCommand` 回调**（适合纯 HTML / 多页应用）

```javascript
window.openChatConfig = {
  baseUrl: '...',
  apiKey: '...',
  onCommand: function(cmd) {
    // cmd = { action: 'openPanel', params: { url: '...' } }
    if (cmd.action === 'openPanel') {
      window.open(cmd.params.url, '_blank')
    }
  }
}
```

> `onCommand` 每次调用接收**单条指令**。当 AI 回复包含多条指令时，`embed.min.js` 内部通过循环逐条调用 `onCommand`，嵌入方无需自行遍历。

**方式二：DOM 事件监听**（适合 Vue / React SPA）

```javascript
window.addEventListener('com.openchat.embed', function(e) {
  if (e.detail.action === 'command') {
    e.detail.commands.forEach(function(cmd) {
      if (cmd.action === 'navigate') {
        router.push(cmd.params.path)  // Vue Router
      }
    })
  }
})
```

> DOM 事件的 `e.detail.commands` 是指令**数组**，需要自行遍历处理。

> **协议常量**：事件名 `com.openchat.embed` 和 `action: 'command'` 由 open-chat 服务定义，集成时请直接使用这些固定值。

两种方式二选一：若定义了 `onCommand`，则不触发 DOM 事件；未定义 `onCommand` 时才触发 DOM 事件。

### postMessage 协议

```javascript
// iframe → 宿主
{
  type: 'com.openchat.embed',    // 消息来源标识
  action: 'command',             // 操作类型
  commands: [                    // 指令数组
    { action: 'openPanel', params: { url: '...' } }
  ]
}
```

## 参数注入（getAgentParams）

嵌入模式下，宿主系统可以向对话弹窗注入智能体参数值（如用户信息、会话 token 等）。

### 调用时机

每次**切换智能体**、**切换会话**、**发送消息前**都会调用，宿主根据上下文决定返回哪些参数值。

### 回调签名

```typescript
getAgentParams?: (context: {
  agentId: string          // 当前智能体 ID
  agentName: string        // 智能体名称
  backendType: string      // 后端类型（dify / direct_llm / fastgpt / n8n）
  paramKeys: string[]      // 智能体所有参数的 key 列表
}) => Promise<Record<string, any>>
```

返回的对象中，key 为参数名，value 为参数值。返回空对象 `{}` 表示不注入任何值。

### 集成方式

open-chat 按以下优先级查找回调：

1. `openChatConfig.getAgentParams` — 直接在配置中定义，**优先使用**
2. `window.__getAgentConversationParams` — 全局桥接函数，当 `getAgentParams` 未配置时作为备选

> **优先级说明**：如果 `openChatConfig` 中配置了 `getAgentParams`，则始终调用它获取参数值；只有当 `getAgentParams` 为 `undefined`（未配置）时，才会调用 `window.__getAgentConversationParams`。两者不会同时调用。

根据参数值是否需要访问框架内部状态，选择不同的集成方式：

#### 场景一：参数值固定，不需要访问框架状态

适用于所有工程类型（纯 HTML、Vue、React 等）。直接在 `openChatConfig` 中定义回调函数：

```html
<script>
window.openChatConfig = {
  baseUrl: '...',
  apiKey: '...',
  getAgentParams: async function(ctx) {
    // ctx = { agentId, agentName, backendType, paramKeys }
    return {
      app_version: '1.0',
      env: 'production',
      user_name: '张三',
      current_time: new Date().toLocaleString(),
    }
  }
}
</script>
<script src="embed.min.js" defer></script>
```

这种方式不依赖任何框架，回调函数在 `index.html` 中直接定义，不存在时序问题。

#### 场景二：参数值动态，需要访问 Vue store / React state

Vue/React SPA 中，如果参数值依赖框架内部状态（如登录用户信息、路由等），`openChatConfig` 定义时框架尚未初始化，无法直接访问 store。此时应注册全局桥接函数。

**`index.html`**：只写基础配置，**不写 `getAgentParams`**：

```html
<script>
window.openChatConfig = {
  baseUrl: '...',
  apiKey: '...',
  // 不写 getAgentParams
}
</script>
<script src="embed.min.js" defer></script>
<div id="app"></div>
<script src="/vue-app.js"></script>
```

**Vue 应用入口**（如 `main.ts`）：注册全局桥接函数：

```javascript
import store from './store'

window.__getAgentConversationParams = async function(ctx) {
  return {
    user_name: store.state.user.name,
    token: store.state.auth.token,
    current_page: router.currentRoute.value.path,
  }
}
```

**React 应用**（根组件或入口）：注册全局桥接函数：

```jsx
useEffect(() => {
  window.__getAgentConversationParams = async (ctx) => {
    return {
      user_name: user.name,
      token: auth.token,
    }
  }
  return () => { delete window.__getAgentConversationParams }
}, [user, auth])
```

### 注意事项

**时序问题**

`openChatConfig` 在 `index.html` 中解析时会立即求值。以下写法会导致回调永远是 `undefined`：

```html
<!-- ❌ 错误：此时 Vue 尚未 mount，window.__getAgentConversationParams 是 undefined -->
<script>
window.openChatConfig = {
  getAgentParams: window.__getAgentConversationParams,  // 求值后为 undefined，不会随 Vue mount 更新
}
</script>
```

以下写法没有时序问题（函数直接定义，不引用外部变量）：

```html
<!-- ✅ 正确：直接定义函数 -->
<script>
window.openChatConfig = {
  getAgentParams: async function(ctx) { return { user_name: '张三' } }
}
</script>
```

**总结**：
- 直接定义函数 → 任何时候都可用，无时序问题
- 引用 `window.__getAgentConversationParams` → 有时序问题，不要在 config 中引用

**回调执行是异步的**

`getAgentParams` 是 `async` 函数，open-chat 会 `await` 它的返回值。如果宿主需要从远程接口获取参数值，可以直接在函数中发请求，open-chat 会等待请求完成后再继续。但请注意：

- 如果回调长时间不返回，用户发送消息会被阻塞
- 建议为远程请求设置超时（如 5 秒），超时后返回 `{}`，使用表单现有值

**跨域限制**

`embed.min.js` 通过 `iframe.contentWindow` 将回调透传给 iframe，这要求宿主页面和 iframe 同源。如果不同源，透传会静默失败，此时 open-chat 只能从 `window.__getAgentConversationParams` 读取（iframe 内部的全局变量）。

### 使用场景对照

| 场景 | 推荐方式 | 示例 |
|------|---------|------|
| 参数值固定，不需要访问框架状态 | `openChatConfig.getAgentParams` | `app_version`、`env`、固定用户名 |
| 参数值动态，需要访问 Vue/React 状态 | `window.__getAgentConversationParams` | 登录用户信息、当前路由、token |
| 两者都配置了 | `getAgentParams` 优先，`__getAgentConversationParams` 不会被调用 | — |

### 合并策略

宿主返回的参数值与表单现有值合并：

- 宿主返回了的 key → 覆盖表单值（用户可在表单中再次修改）
- 宿主未返回的 key → 保持用户已填写的值（不清空）
- 宿主调用失败或无回调 → 使用表单现有值

> **一次性参数**：对于需要每次发送都更新的参数（如 `session_token`、`current_time`），宿主每次返回新值即可。用户在表单中修改后，下次发送时会被宿主新值覆盖。

### 回调参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `agentId` | `string` | 当前智能体 ID |
| `agentName` | `string` | 智能体名称 |
| `backendType` | `string` | 后端类型（`dify` / `direct_llm` / `fastgpt` / `n8n`） |
| `paramKeys` | `string[]` | 智能体所有参数的 key 列表（包括非必填项） |

宿主可根据 `agentId` 区分不同智能体返回不同参数，根据 `paramKeys` 决定填充哪些参数。

### 协议常量

回调参数中的字段名（`agentId`、`agentName`、`backendType`、`paramKeys`）由 open-chat 服务定义，集成时请直接使用。

## 常见问题

### 窗口没有显示 / 401 错误

检查：
1. `apiKey` 是否正确（在管理面板的 API Keys 页面确认）
2. `baseUrl` 是否能通（浏览器访问 `baseUrl/embed` 看是否返回页面）
3. 控制台是否有 `[open-chat-embed]` 错误日志

### 浮动按钮位置不对

- 初始位置：右下角，距边缘 24px
- 拖动后会保存新位置
- 如果位置异常，在 DevTools 中删除 `open_chat_embed_state` 后刷新页面复位

### 弹窗中对话内容不全

iframe 加载需要时间，确保 open-chat 服务器正常运行。打开浏览器 DevTools Network 面板查看 `/api/chat-messages` 请求是否返回 200。

### 跨域问题

如果集成网站和 open-chat 服务器不同域名：
- `embed.min.js` 和 `/embed` 页面必须同域（iframe 同源策略）
- 如果必须跨域，需要 open-chat 服务端配置 CORS 和 `SameSite=None; Secure` cookie
