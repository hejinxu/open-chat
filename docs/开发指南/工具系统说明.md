# 工具系统说明

> 基于当前代码实现梳理，覆盖工具系统架构、各内置工具实现逻辑、联网开关（`enable_network`）控制规则与安全边界。

## 一、工具系统架构

### 1.1 ToolRegistry 注册中心

- **文件**：`webapp/lib/tools/registry.ts`
- **全局单例**：`getToolRegistry()` 首次调用时自动注册全部内置工具（`allBuiltinTools`），后续复用同一实例
- **`pendingToolCalls`**：使用 `globalThis` 存储（`__openchat_pendingToolCalls`），确保开发模式 HMR 安全，用于客户端工具执行结果回传
- **`toLangChainTools(context?, excludeNames?)`**：将启用工具转为 LangChain `DynamicStructuredTool` 列表；`excludeNames` 用于按 agent 剔除工具（如关闭联网时排除 `web_search`）

### 1.2 工具定义结构（`ToolDefinition`）

| 字段 | 说明 |
|------|------|
| `name` | 工具名（模型调用标识） |
| `displayName` | 展示名 |
| `description` | 工具描述（模型据此决定何时调用） |
| `category` | `builtin` / `mcp` / `custom` |
| `execution` | `server`（服务端执行）/ `client`（客户端经 SSE 执行） |
| `inputSchema` | JSON Schema 输入定义 |
| `handler` | 执行函数 `(input, context) => Promise<ToolResult>` |

### 1.3 内置工具清单

`allBuiltinTools`（`webapp/lib/tools/builtin/index.ts`）组成：

| 工具名 | 文件 | 执行位置 | 描述 |
|--------|------|----------|------|
| `get_page_content` | browser-tools.ts | client | 获取宿主页面 DOM 内容 |
| `get_selected_text` | browser-tools.ts | client | 获取用户选中的文本 |
| `get_element_by_selector` | browser-tools.ts | client | 按 CSS 选择器获取元素 |
| `http_request` | server-tools.ts | server | 发送 HTTP 请求 |
| `fetch_url` | fetch-url.ts | server | 抓取网页内容或搜索互联网 |
| `get_current_time` | time-tools.ts | server | 获取当前时间 |
| `execute_sql` | execute-sql.ts | server | 在配置的数据源上执行只读 SQL |

> 注：`web_search`（web-search.ts）已实现但**未注册**，见下文「五、联网开关」说明。

## 二、内置工具实现逻辑

### 2.1 execute_sql（数据查询）

**用途**：问数智能体（`data_query`）的 SQL 查询工具。

**执行流程**：
1. **应用层只读校验** `validateReadOnlySql`：
   - 多语句检查（分号拼接即拒绝）
   - 危险关键词黑名单：INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE / CREATE / GRANT / REVOKE / EXEC / INTO / REPLACE / MERGE / UPSERT（`\b` 单词边界，先剔除字符串字面量防误判）
   - 必须以 SELECT 或 WITH 开头
2. **结构校验**（代码级，零 LLM）：解析 SQL 引用的表与带别名的列，与实时 schema（`information_schema`，TTL 缓存 60s）比对，拦截不存在的表/列（如 `YEAR`），返回友好错误让模型修正
3. **同请求重复查询拦截**：归一化后的相同 SQL 直接返回缓存结果，成功结果附带引导，避免模型反复执行相似查询
4. **方言分派与只读保护**：按 `getDialect(type).family` 分派执行（mysql 族走 mysql2 / PG 族走 `pg`），只读保护用 `dialect.setupReadOnly()`（MySQL `SET SESSION TRANSACTION READ ONLY` / PG 族 `SET default_transaction_read_only = true`）
5. **结果限制**：自动追加 `LIMIT`（默认 100 行），超时 180 秒

**方言层**：连接/查询/只读按 `lib/services/dialects.ts` 分派。PG 族（postgresql / vastbase / kingbase）复用 `pg` 驱动与 PG 逻辑，连接级 `-c search_path=...` 支持多 schema；vastbase / kingbase 动态提示词强制 `LIMIT/OFFSET` 分页、禁用 Oracle `ROWNUM` 伪列。详见「智能体管理功能改造设计」5.3 / 5.4 节。

**与问数链路的关系**：DDL 由 `lib/services/schema-select.ts` 运行时从数据库实时拉取（注释优先级：用户自定义 > 实时 > 快照），配合渐进式表选择只注入相关表。

### 2.2 fetch_url（网页抓取/搜索）

**输入**：`{ url, search_engine = 'bing' }`

**双重功能，按 `url` 是否带协议前缀分流**：

| 分支 | 条件 | 行为 |
|------|------|------|
| 搜索关键词 | 无 `http/https` 前缀 | 受 `enable_network` 控制；开启时抓取搜索引擎结果页 HTML（`searchWithScraping`，Bing/百度），正则解析文本与链接后返回 |
| 抓取 URL | 有 `http/https` 前缀 | 不受开关限制（可能是内网/用户指定 URL）；`fetch` 抓取页面文本（截断 4000 字符）+ 链接列表，15 秒超时 |

### 2.3 http_request（通用 HTTP 请求）

**输入**：`{ url, method, headers, body, timeout }`

- 通用 HTTP 客户端，`url` 原样传给 `fetch`
- **不支持关键词搜索**：传无协议前缀的"关键词"不是有效 URL
- 与 `fetch_url` 规则一致：无协议前缀视为"搜索关键词"场景，受 `enable_network` 控制（关闭时提示"未启用联网搜索"，开启时提示"URL 必须是完整地址"）
- **完整 URL 不受限**（可能调用业务接口/用户指定，含模型构造的公网 URL）

### 2.4 web_search（搜索引擎 API 搜索）

**输入**：`{ query, count = 5 }`

- 按 `agentConfig.web_search` 配置分发：Bing / SerpAPI / 自定义端点；无配置时走免费 DuckDuckGo
- **当前未注册**：需搜索引擎 API key（Bing/SerpAPI）且 DuckDuckGo 网络不可达，故未加入 `allBuiltinTools`，模型看不到此工具

### 2.5 get_current_time / 浏览器工具

- `get_current_time`：返回指定时区当前时间（服务端）
- 浏览器工具（`get_page_content` 等）：`client` 执行，经 SSE 通知前端获取宿主页面 DOM 内容（嵌入场景使用）

## 三、工具执行流程

### 3.1 服务端工具

```
模型发起 tool_call
  → toolNode（react-agent.ts）
  → ToolRegistry.execute(name, input, context)
  → 校验工具存在 / 启用 / 有 handler
  → 调用 handler(input, fullContext)
  → 返回 ToolResult
```

### 3.2 客户端工具

```
模型发起 tool_call
  → ToolRegistry.executeClientTool
  → 生成 tool_call_id，经 SSE 发送 tool_call 事件到前端
  → 前端执行并回传（/api/tools 接口 resolveClientToolResult）
  → 超时 30 秒
```

## 四、上下文（ToolContext）

工具执行时传入 `ToolContext`，常用字段：

| 字段 | 说明 |
|------|------|
| `agentConfig` | 当前 agent 的 `agent_config`（含数据源、联网开关、搜索配置等） |
| `queryContext` | 问数链路运行时上下文（`canonicalQuery`、`dialect`、`enableSemanticCheck`、`llm`、同请求 SQL 缓存） |
| `controller` | SSE 控制器（客户端工具通知） |
| `pendingToolCalls` | 客户端工具回传 Map |

## 五、联网开关（enable_network）

### 5.1 语义

- **`enable_network === true` 才允许联网搜索**；`!== true`（`false` 或未配置）一律视为关闭。
- 默认未配置即关闭（问数等 agent 默认不允许搜索类工具）。

### 5.2 判断规则（fetch_url / http_request 一致）

- URL 带 `http://` 或 `https://` 前缀 = **抓取/请求**，不受开关限制（可能是内网或用户指定 URL）
- **无协议前缀 = 搜索关键词**，受开关控制，关闭时拒绝并返回"当前智能体未启用联网搜索功能"

### 5.3 各工具行为矩阵

| 工具 | 场景 | `enable_network` 开启 | 关闭/未配置 |
|------|------|------|------|
| `web_search` | 搜索互联网 | 未注册（不可用） | 未注册（不可用） |
| `fetch_url` | 抓取 URL | 允许 | 允许 |
| `fetch_url` | 搜索关键词 | 允许 | **拒绝** |
| `http_request` | 完整 URL 请求 | 允许 | 允许 |
| `http_request` | 非完整 URL（关键词） | 拒绝（非有效 URL） | **拒绝**（提示未启用联网） |

### 5.4 System prompt 提示（`getNetworkStatusPrompt`）

- `enable_network === true`：提示"你可以使用联网搜索和网页抓取工具获取互联网上的最新信息。"
- `!== true`：提示"当前环境不支持联网搜索…只能访问用户明确提供的具体 URL。HTTP 请求工具可用于调用业务系统接口。"

### 5.5 工具列表剔除

`agent-executor.ts` 的 `getExcludedTools()`：`enable_network !== true` 时返回 `['web_search']`，通过 `createReactAgent` / `createPlanAndExecuteAgent` 的 `excludeTools` 参数从绑定给模型的工具列表中剔除。当前 web_search 未注册，此为防御性逻辑；若后续注册 web_search，开启时绑定、关闭时剔除。

### 5.6 已知边界

- **无法阻止"模型构造完整 URL"联网**：工具层无法区分"用户指定的 URL"与"模型自己构造的 URL"。只要允许 URL 访问类工具（`fetch_url` 抓 URL / `http_request`），模型就可能自主访问公网。这是"允许用户指定 URL"这一取舍的必然结果。
- **SSRF 风险**：`http_request` / `fetch_url` 可访问内网地址，模型可能被诱导访问内网敏感资源（如云元数据 `169.254.169.254`）。当前未做内网限制。

## 六、工具注册与扩展

### 6.1 注册新工具

1. 在 `webapp/lib/tools/builtin/` 下新建工具文件，导出 `xxxTools: ToolDefinition[]`
2. 在 `builtin/index.ts` 中导入并加入 `allBuiltinTools`
3. （可选）在管理后台工具配置中声明

### 6.2 web_search 注册条件

如需启用 `web_search`：
1. 配置搜索引擎 API key（Bing/SerpAPI）或保证 DuckDuckGo 可达
2. 将 `webSearchTools` 加入 `builtin/index.ts` 的 `allBuiltinTools`
3. 关闭联网的 agent 将自动通过 `getExcludedTools()` 剔除该工具
